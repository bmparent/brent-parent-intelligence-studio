# Eidos Works security sprint — implementation and release gates

This is a branch candidate paired with the Sentinel Lab backend. It has not been deployed to the public Eidos Works domain. Keep Snapshot capture, generation and checkout disabled; outbound capture still has the documented DNS-rebinding gap.

## Implemented in code

| Control | Behavior |
| --- | --- |
| Owner identity | Owner endpoints verify the Cloudflare Access application JWT signature against the team's rotating JWKS, its issuer, audience, issue/expiry times and one exact owner email. A forged or expired assertion cannot fall through to a bearer token. A missing Access assertion denies by default. The legacy bearer token is allowed only for an explicit automation setting or local test mode. |
| Owner audit | An authorized request writes an actor, HTTP method, bounded path, event and UTC time before any owner work starts. No token, body, prompt, email from the request, or IP is written. If the audit DB fails, the owner action fails closed. `/api/operations/audit?limit=50` reads the latest entries after authenticating and logging its own read. Platform and growth audit records expire after 90 days through their existing maintenance/collection paths. |
| Inquiry abuse | Private mailer and webhook delivery both require a verified Turnstile token with the exact request hostname and `inquiry` action. Shared durable limits are five submissions per hashed IP per hour, three per hashed email per day and 100 total per day. On failed verification, missing bindings, exhausted quota or provider failure, the form returns its prepared email fallback without claiming delivery. Raw IP and email are absent from quota keys. |
| Playground quotas | Project saves are limited to 60/account/hour; new checkout attempts to 5/account/day while retries for an existing request ID remain possible. Paid Playground AI retains lifetime reservations and gains atomic daily account/global micro-dollar reservations. Defaults are the smaller of the configured lifetime budget and 250,000/1,000,000 micro-dollars; explicitly configured daily caps cannot exceed lifetime caps. Existing AI kill switches remain off. |
| Browser policy | Static Pages assets receive enforced CSP with external script allowlists, no `unsafe-inline` for scripts, restricted images/connect/frame destinations, `form-action`, `frame-ancestors`, and `object-src 'none'`. Styles retain `unsafe-inline` for current React/animation styles. Static assets receive one-year HSTS without `includeSubDomains`. `_headers` does not attach headers to Pages Functions responses; those routes have their own response headers. |

## Provision before paired preview

1. Apply `migrations/0007_owner_audit.sql` to the isolated Sentinel database and `migrations/growth/0002_owner_audit.sql` to the isolated Pages growth database. Preserve existing data and migrations. The growth collector expects the new table during retention cleanup.
2. Create one Cloudflare Access self-hosted application for the exact Pages preview hostname with these protected paths in its public destinations: `/api/operations/*`, `/api/community/moderate`, `/community/moderate*`, `/api/growth/report`. All owner routes must use this one application's audience; the code accepts one audience. Include `/api/community/maintenance` only if its scheduled service caller has a scoped Access Service Auth policy; the independent maintenance bearer secret continues to be audited. Give the human owner an exact-identity allow policy with MFA at the identity provider and an application session no longer than 24 hours. Confirm each intended path is actually protected at the edge; do not protect public API, Turnstile or Stripe webhook paths.
3. Set `EIDOS_ACCESS_TEAM_DOMAIN` (the exact `<team>.cloudflareaccess.com` hostname), `EIDOS_ACCESS_AUD` (that application's audience), and `EIDOS_OWNER_EMAIL` (the exact verified owner email) on the paired backend. Set the same three variables on Pages for its direct `/api/growth/report` Function. Set `EIDOS_ADMIN_AUTOMATION_ALLOWED=false` or leave it unset by default.
4. Bind `EIDOS_GROWTH_DB`, `EIDOS_PLATFORM_TOKEN` (at least 32 characters), `TURNSTILE_SITE_KEY` and `TURNSTILE_SECRET_KEY` on Pages, with a Turnstile widget authorized for the exact preview hostname. Confirm `CF-Connecting-IP` arrives at the inquiry Function. The relay continues to require the paired backend's separately configured platform token and exact site-origin allowlist.
5. If scheduled readiness or growth reporting must use a service identity, create a path-scoped Access Service Auth policy and pass its `CF_ACCESS_CLIENT_ID`/`CF_ACCESS_CLIENT_SECRET` in the existing scripts, plus their existing independent bearer credential. Only then set `EIDOS_ADMIN_AUTOMATION_ALLOWED=true` for that runtime. The automation path logs actor `automation`; remove this flag and its bearer if no automation is needed. For an interactive owner script, a valid app JWT can be supplied as `EIDOS_OWNER_ACCESS_JWT` (sent as a scoped Access cookie and assertion). Do not store these credentials in URLs, logs or the repository.
6. Optionally configure Cloudflare WAF rate rules or managed challenges at the edge for public high-cost routes, after testing the provider's bot/Turnstile and webhook exclusions. Application quotas above are enforced even without a WAF rule; no provider WAF change is included in this branch.

- In a real Access-protected preview browser, check an unauthenticated owner path denies, the exact owner with MFA succeeds, a different authenticated identity denies, and audit rows appear. Verify a maintenance service request separately if automation is configured. Confirm replay/tampered/expired JWTs deny at the application layer.
- Check successful inquiry delivery with a real Turnstile token and controlled inbox, token reuse/expiry and 429 fallback, no duplicate provider deliveries, and permitted hostnames. Check save/checkout limits and daily AI budget in the isolated database without enabling paid AI.
- Inspect actual deployed static response headers and browser console on Home, Contact, Friction Review, account, Insights, Playground, and checkout/test paths. Resolve legitimate CSP violations before exposing the enforced policy; confirm the analytics/Turnstile flows and loaded images. Functions require a separate header check because Pages ignores `_headers` for their responses.

Do not merge `main` or change the canonical production alias until the paired release gates and an exact production deployment are approved.
