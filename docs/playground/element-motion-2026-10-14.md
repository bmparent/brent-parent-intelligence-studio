# Selected-element motion and cancellation acceptance

The unified block inspector now applies a bounded entrance to the selected element. Choose **Element motion → Entrance**: None, Fade in, Gentle rise, or Soft settle. Duration accepts 200–1600 ms and delay accepts 0–1200 ms. **Remove motion** restores the static element. Each committed control change is one normal project history entry; Undo includes the explicit schema upgrade when applying motion to a schema-4 block project.

Motion runs once when the visitor page opens, including when entering Preview. It does not wait for scrolling. Rise moves at most 16 px; settle scales from 98%. These transforms do not rearrange the document flow. Motion is off while editing, so outlines, selection, drag and crop coordinates stay stable. Both the operating system's reduced-motion preference and the project's existing reduced-motion preference suppress it. Without JavaScript, the content remains visible and static. Mobile uses the same element setting; layout overrides remain independent.

This uses optional `BlockNode.motion = { preset, duration, delay }` inside the existing schema-5 project. Validation rejects unknown properties, unsupported presets and non-finite/out-of-range numbers. Schema 1–4 cannot silently accept this metadata. The new control explicitly upgrades a schema-4 block project to 5 in the same Undo step. No second store, provider call or new animation engine is involved. The existing standalone Motion Studio and its document/export format are preserved; its timeline is not imported into an element entrance.

`authoringRenderer.ts` supplies the same CSS and markup to the editor, local ZIP and server package contract. Projects without motion receive no new motion CSS or attributes. Snapshot delivery remains subject to the existing disabled-by-default TEST gate and requires the separately mirrored renderer graph; local UI success is not hosted delivery acceptance.

## Boundaries

Local browser viewports are not physical-device acceptance. GPU-disabled Chromium checks a fallback environment, not device GPU performance. Animation APIs sample rendered motion but do not measure actual display presentation latency. Six to eight unfamiliar target users and representative physical-device acceptance remain external validation gates. No AI, payment, mail or hosted configuration was enabled by this change.
