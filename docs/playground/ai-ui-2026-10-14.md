# Eidos assistance UI — October 14, 2026

The unified editor now has a collapsed **Ask Eidos** control in its selection inspector and Brand view. Opening it checks public configuration, the signed-in account, and the server AI ledger. It requires the dedicated `playgroundAiReady` flag, independently available accounts, a signed-in owner, and an enabled ledger route. The older `aiReady` flag cannot activate Playground generation. Merely opening or editing a local project does not request an AI quote or generation.

## Request and review behavior

1. Choose **This element**, **This section**, **Whole page**, or **Shared brand** and enter a brief.
2. Request a server quote. The request includes the current document ID, revision, selected target, and a validated context projection. Uploaded image bytes, media metadata, standalone artwork/motion payloads, and paid archives are excluded.
3. Review the server model/rate-card identity, estimate, frozen maximum, scope, and expiry. Generation requires a separate explicit confirmation carrying that exact server maximum.
4. Review the typed before/after changes. **Preview proposed page** uses the existing renderer in read-only mode; **Show current design** returns to the actual draft. Neither preview changes the saved project. Header, checklist and footer Finish controls are disabled while a comparison is visible; an unapplied proposal cannot appear to be the purchasable draft.
5. **Apply** validates the full current project and creates one ordinary Undo entry. It preserves assets excluded from the provider context. Apply makes no second generation request. **Discard** changes no project data and does not refund usable generated output.

Quotes and proposals capture the document, revision, selected section/element, Brand view, instruction, scope, authenticated username, and full-project hash. Changes to that context disable stale confirmation or Apply. Apply rechecks the signed-in account and current project before committing. Textual review labels use product names such as Text, Shared typography, or Section order rather than internal field keys.

## Spending and uncertain results

The balance panel displays included and purchased available funds separately, settled AI usage and its included/purchased portions, pending reservations, remaining monthly allowance, requested limit, and exact reset timestamp. The reset is also shown in the viewer's local time. Lowering a limit preserves existing commitments and explains their effective floor. Explicitly saving a limit does not purchase funds or enable recharge.

All amounts come from validated server receipts in integer USD microdollars. The client rejects negative/invalid money, charges above the approved maximum, inconsistent monthly totals/floors, incompatible action states, and changed frozen quote identity. The server remains authoritative for admission, funding, ownership, concurrency, dispatch and settlement.

Before generation the client latches the action as requiring status. A network failure or **Stop waiting** cannot expose another confirmation until a read of that same action resolves the uncertainty. Status reads never resubmit generation. Pending actual charges are displayed as **Pending confirmation**, rather than an invented zero. The action ID is retained in private browser session storage with its username; reload/Continue can retrieve its status, but a restored receipt without the initiating review context cannot be applied.

## Limits

The browser responses are controlled fixtures with zero real provider calls and zero real charges. They prove the UI's handling of server receipts, not hosted provider access, real account isolation, provider quality, hard-cap enforcement, payment or inbox delivery. Those have separate backend and hosted acceptance gates. Public/manual previews keep account and generation flags off until their own acceptance. Brent approved a dedicated Playground key and a total $5 provider-test budget; that authorization is distinct from successful secure credential provisioning or real usage evidence.

Viewport tests are not physical-device or unfamiliar-user acceptance. A browser close/timeout does not establish provider cancellation. Session metadata is a recovery convenience and grants no server access; every status/cancellation request still requires the authenticated owner.
