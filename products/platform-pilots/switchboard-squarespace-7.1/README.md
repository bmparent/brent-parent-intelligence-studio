# Switchboard — Squarespace 7.1 existing-site kit pilot

Version 1.0.0. Status: **unavailable for purchase; hosted installation blocked by missing authorized Squarespace 7.1 editor/test site**. This kit is a manual native-section recipe plus optional CSS and one optional code-block interaction. It is not a theme ZIP, starter-site transfer, or automatic replacement for your current design.

## What is included

- `native-section-recipe.md`: five-page layout/content recipe using Squarespace's native text, image, button, and form blocks. Native copy, imagery, section order, and links remain visually editable.
- `styles.css`: optional scoped section styling. Selecting target section IDs and editing CSS requires code knowledge.
- `selector.html`: optional self-contained service-inquiry Code block. Its text and links are edited in HTML, not native text/image controls. Without JavaScript, ordinary service links and every description remain available.
- `effects.js`: optional enhancement that shows the chosen description without navigation. Static content remains the default if it fails or is removed.
- `preview.html`: local kit preview, not a Squarespace installation receipt.

No booking/payment processor, email delivery, form connection, Squarespace subscription, Eidos service, images, custom fonts, or third-party paid dependencies are included. The kit uses the Switchboard system palette and operating-system fonts. Use your own cleared business photography; do not copy imagery from another template's demo.

## Platform and plan requirements

Confirm **Version 7.1** at the bottom of Pages. Native sections and Site Styles are the baseline. Custom CSS and code blocks containing HTML/CSS can use current Basic, Core, Plus, or Advanced plans. The optional JavaScript enhancement/code injection requires **Core, Plus, Advanced, or a qualifying legacy plan**. Verify the actual plan before installation. Use the static section on Basic. There is no server-side PHP/SQL or 7.1 Developer Platform import route.

## Install and connect

1. Record current pages, URL slugs, fonts, colors, forms, integration settings, and published appearance. Work on new hidden/test pages first. Do not replace existing live pages or customer data.
2. Follow `native-section-recipe.md`. Add or duplicate native pages manually. Keep existing slugs unless you intentionally configure redirects. Replace sample business text/photos through native block controls.
3. Set Site Styles: ink `#14302b`, paper `#f6f6ee`, accent `#d8f35f`, pale surface `#dce9e2`; sans-serif headings/body, generous spacing, high contrast. Squarespace font choices may differ from system fonts; record the selected family and verify redistribution rules if supplying any font separately.
4. Optionally add `styles.css` in Custom CSS after replacing its target section ID. Only target intended sections. Site Styles remain the simplest route; CSS is optional.
5. For the selector, add one Code block, select HTML mode, turn Display Source off, and paste `selector.html`. Replace all example.com links and sample copy **in that block**. Do not claim its copy is visually editable. On Core/higher, paste `effects.js` inside `<script>…</script>` in page footer injection. Omit it entirely for the static alternative. Use only one selector ID per page.
6. Configure the Contact page's native Form block with the buyer's chosen storage/email destination and privacy notice. Send an authorized test message and confirm actual receipt. Connect any supported booking service separately and verify its publication/plan costs. A button alone is not a working integration.
7. Preview desktop/mobile and signed-out browsing. Check each service path, keyboard focus, all descriptions with scripts disabled, long copy, missing images, native navigation, form receipt, and any external booking link. Publish a **test** page and retain its URL/screenshots/plan/browser/date before enabling purchase eligibility.

## Removal and recovery

Remove page injection first, then the optional code block/CSS. Native content remains editable. Restore saved Site Styles and original pages/URLs from your recorded state. Keep form data and integrations independent of this kit. If code does not render while signed in, test the published test page in a private browser; do not assume the editor view is the customer experience. Platform support excludes troubleshooting third-party code. Draft support/update terms require commercial approval; no setup time has been promised.
